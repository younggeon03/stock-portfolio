# 운영

세팅부터 실행, 테스트, 장애 대응까지입니다. 실무의 런북처럼 **순서대로 따라 하거나 증상으로 찾는** 문서입니다.
구조 설명은 [아키텍처](아키텍처.md), 앞으로 할 일은 [로드맵](로드맵.md)에 있습니다.

## 2. 키 넣기

```bash
cp .env.example .env     # 값을 채웁니다. .env 는 .gitignore 에 있어 커밋되지 않습니다
```

- `SEC_USER_AGENT` 는 키가 아니라 SEC 가 요구하는 연락처입니다. "앱이름 이메일" 형식이 아니면 403 입니다
- 계좌 번호(`TOSS_ACCOUNT_SEQ`, `NAMUH_ACCOUNT_NO`)는 **처음엔 비워두고** 5장에서 채웁니다
- `OWNER_PASSWORD` 를 넣으면 내 영역(잔고·증권사·분석·스크린샷·Swagger)이 로그인 뒤로 갑니다. 아이디는 `owner`(바꾸려면 `OWNER_USERNAME`). **비우면 로그인 없이 전부 열립니다** — 내 PC 개발용이고 기동 로그에 경고가 찍힙니다. 서버에서는 필수이고, HTTPS 뒤라면 `COOKIE_SECURE=true` 도 같이
- `TOKEN_ENCRYPTION_KEY` 를 넣으면 증권사 토큰을 DB 에 암호화해서 저장합니다. 만드는 명령은 `.env.example` 7번에 있습니다. 내 PC 에서는 선택, **서버에서는 필수**입니다. 비어 있으면 기동 로그에 경고가 찍힙니다

### 토스 허용 IP 등록

건너뛰면 토스가 전부 403 입니다. 토스증권 WTS → 설정 → Open API → **허용 IP 관리**에 지금 공인 IP 를 넣습니다.
내 IP 는 <https://ifconfig.me>, 앱을 띄운 뒤라면 403 에러 메시지가 직접 알려줍니다.

> 목록이 비어 있으면 전부 통과하지만 하나라도 등록하면 등록된 것만 통과합니다. 학교 망은 하루에 한 번꼴로, 휴대폰 핫스팟은 30분 안에도 바뀝니다.

## 3. 실행 — 도커 (권장)

앱과 MySQL 을 같이 띄웁니다. DB 를 따로 설치할 필요가 없습니다.

```bash
docker compose up -d --build     # 첫 빌드 2~3분
docker compose logs -f app       # "Started PortfolioApplication" 이 보이면 준비 완료
docker compose down              # 끄기. DB 데이터는 볼륨에 남음
```

- 앱 설정은 `.env` 를 그대로 읽습니다. DB 주소만 compose 가 `mysql` 서비스로 덮어씁니다
- DB 데이터는 `mysql-data` 볼륨에 있습니다. 지우려면 `docker compose down -v`
- 로컬에 이미 MySQL 이 3306 을 쓰고 있어도 됩니다. 컨테이너 MySQL 은 바깥으로 포트를 열지 않습니다

## 6. 테스트와 CI

```bash
./mvnw.cmd test      # 158개. 외부 API·DB 를 안 불러 키 없이 돕니다
```

PR 을 열거나 `main` 이 바뀌면 GitHub Actions(`.github/workflows/ci.yml`)가 같은 테스트를 돌리고 도커 이미지까지 빌드합니다. 실패하면 PR 에 빨간 X 가 뜹니다.
같이 도는 **배포 설정 검사** 는 `deploy/` 를 봅니다: compose 해석(관측 켬·끔 둘 다), `promtool check config`, 대시보드 JSON·uid. 이것도 비밀값 없이 돕니다. 병합 필수 검사(아래 두 개)에는 아직 넣지 않았습니다.
CI 에는 비밀값이 필요 없습니다. 테스트가 바깥을 부르지 않게 만들어 뒀기 때문입니다.

**테스트 커버리지는 CI 에서만 잽니다.** 실행 화면(Summary)에 패키지별 줄 커버리지 표가 뜨고, 보고서 전체는 `jacoco-report` 로 내려받습니다. 내 PC 는 경로에 한글(`주식`)이 있어 JaCoCo 에이전트 경로가 깨져 보고서가 안 생깁니다(테스트는 정상).
외부 API 를 부르는 클라이언트는 키가 필요해 테스트하지 않으므로 전체 숫자는 낮게 나옵니다. 계산하는 코드(`service`, `external.filing`·`dart`·`edgar`)가 덮여 있는지를 보세요.

### 변경을 합치는 법 (PR)

`main` 은 보호돼 있습니다. **직접 푸시와 강제 푸시가 막혀 있고, 관리자도 예외가 아닙니다.**

```bash
git switch -c feat/무엇을-하는지         # 1. 브랜치
# ... 고치고 커밋 ...
git push -u origin HEAD                  # 2. 푸시
gh pr create --fill                      # 3. PR
gh pr checks --watch                     # 4. CI 두 개(테스트와 패키징, 도커 이미지 빌드)가 초록인지
gh pr merge --squash                     # 5. 스쿼시 병합. 브랜치는 자동으로 지워짐
git switch main && git pull              # 6. 로컬 main 맞추기
```

| 규칙 | 왜 |
|---|---|
| CI 두 개가 통과해야 병합 | 깨진 코드가 `main` 에 못 들어감 |
| 브랜치가 `main` 최신이어야 병합 | 각자는 통과해도 합치면 깨지는 경우를 막음 |
| 스쿼시 병합만, 선형 이력 | PR 하나가 커밋 하나. 되돌릴 때 PR 단위로 |
| 리뷰 승인 0명 | 혼자 하는 프로젝트라 자기 PR 을 승인할 수 없음. 팀이면 1명 이상으로 |

저장소는 공개입니다. 커밋·PR·이슈에 실제 잔고, 계좌, 키, IP 를 쓰지 마세요. 2026-09-30 공개 전에 이력을 한 커밋으로 정리했습니다.

### 스키마 바꾸기

테이블은 Flyway 가 `src/main/resources/db/migration/` 의 SQL 로 만듭니다. Hibernate 는 검사만 합니다.

1. 엔티티를 고친다
2. 다음 번호로 SQL 파일을 만든다. 예: `V2__company_analysis_add_currency.sql`
3. 앱을 띄우면 Flyway 가 V2 를 적용하고, Hibernate 가 엔티티와 맞는지 검사한다

- **이미 적용된 V 파일은 고치지 마세요.** Flyway 가 파일 내용의 체크섬을 기록해 둬서, 고치면 다음 기동이 멈춥니다. 고칠 게 있으면 새 번호로 덧붙입니다
- 컬럼을 지우거나 이름을 바꾸는 것도 SQL 로 직접 씁니다. 예전(`ddl-auto: update`)에는 이게 조용히 반영되지 않았습니다
- Flyway 를 붙이기 전부터 테이블이 있던 DB 는 처음 한 번 "V1 까지 적용됨" 으로 표시만 합니다(baseline). 빈 DB 는 V1 부터 실행합니다

## 7. 배포

PR 을 합치면 사람 손 없이 서버가 바뀝니다. 파일은 전부 `deploy/` 에 있습니다.

| 파일 | 하는 일 |
|---|---|
| `compose.yml` | app(이미지) + mysql + Caddy. 앱 포트는 바깥에 안 열고 Caddy(80·443)만 엽니다. 관측(prometheus·grafana)은 profile `monitoring` 일 때만 뜹니다 |
| `Caddyfile` | HTTPS 자동 발급, 앱이 다시 뜨는 동안 요청을 최대 30초 잡아둠, `/actuator` 차단 |
| `deploy.sh` | 이미지 교체 → 헬스체크 → 실패하면 바로 앞 버전으로 되돌림 |
| `backup.sh` | DB 덤프 (cron 매일 04:00, 14일 보관) |
| `server-setup.sh` | 새 서버 한 번 준비: 도커, 방화벽, 스왑, 시간대, cron |
| `env.example` | 서버 `.env` 견본 |
| `monitoring/` | `prometheus.yml`(무엇을 긁나), Grafana 데이터소스·대시보드 프로비저닝, 대시보드 JSON. [지표 보기](#지표-보기) |

### 처음 한 번

1. **서버 만들기**: 오라클 클라우드 Always Free, 우분투, 홈 리전 서울. 콘솔의 보안 목록(Security List)에서 TCP 80·443 을 엽니다
2. **도메인**: DNS A 레코드를 서버 공인 IP 로. HTTPS 발급에 필요합니다
3. **서버 준비**
   ```bash
   scp -r deploy ubuntu@서버IP:~/stock-portfolio
   ssh ubuntu@서버IP 'bash ~/stock-portfolio/server-setup.sh'
   ```
4. **서버 `.env`**: `cp env.example .env && chmod 600 .env` 후 채웁니다. ★ 값이 빠지면 `deploy.sh` 가 배포를 멈춥니다 (로그인 꺼진 채로 공개되는 사고를 막으려고)
   - **값 뒤의 같은 줄 설명(`# ...`)은 지웁니다.** 값을 비워 둔 채 `KEY=   # 설명` 으로 남기면 compose 가 `# 설명` 을 값으로 읽습니다. `deploy.sh` 는 이것도 빈 값으로 보고 멈춥니다(빈 따옴표 `""` 도). `#abc` 처럼 바로 붙은 `#` 은 정상 값입니다
   - **관측**: `COMPOSE_PROFILES=monitoring` 이면 Prometheus·Grafana 가 같이 뜨고 `GRAFANA_ADMIN_PASSWORD` 가 ★ 필수가 됩니다(`openssl rand -base64 24`). 메모리 1GB 서버면 `COMPOSE_PROFILES` 줄을 지웁니다. 그러면 Grafana 비밀번호 없이도 배포됩니다
5. **배포 키**: 내 PC 에서 배포 전용 키를 만들어 공개키만 서버에 넣습니다
   ```bash
   ssh-keygen -t ed25519 -f deploy_key -N ""      # 개인키는 GitHub Secrets 에만, 파일은 지웁니다
   ssh ubuntu@서버IP 'cat >> ~/.ssh/authorized_keys' < deploy_key.pub
   ssh-keyscan 서버IP                              # 결과를 DEPLOY_KNOWN_HOSTS 에
   ```
6. **GitHub Secrets**: `DEPLOY_HOST`, `DEPLOY_USER`(ubuntu), `DEPLOY_SSH_KEY`, `DEPLOY_KNOWN_HOSTS`. 이게 없으면 배포 워크플로는 건너뜁니다
7. **첫 배포**: Actions → 배포 → Run workflow (태그 비움). 또는 서버에서 `docker login ghcr.io` 후 `./deploy.sh`
8. **토스 허용 IP 에 서버 공인 IP 등록**. 이걸로 IP 가 바뀌는 문제가 끝납니다

### 평소: 합치면 배포

`main` 에 PR 이 합쳐지면 CI 가 `sha-xxxxxxx` 이미지를 올리고, 성공하면 **배포** 워크플로가 이어서 돕니다.
워크플로는 그 커밋의 `deploy/` 파일을 서버에 올리고 `./deploy.sh sha-xxxxxxx` 를 부릅니다. compose·Caddyfile 변경도 코드와 같이 배포됩니다.

이미지 저장소 로그인은 그 작업 동안만 유효한 토큰으로 합니다. 서버에 오래 사는 토큰을 두지 않습니다.

### 되돌리기

| 상황 | 방법 |
|---|---|
| 새 버전이 안 뜸 | 자동. `deploy.sh` 가 헬스체크(`/actuator/health/readiness`) 실패를 보고 바로 앞 버전으로 되돌리고, 워크플로는 빨간불 |
| 떴는데 기능이 잘못됨 | 서버에서 `./deploy.sh --rollback`, 또는 Actions → 배포 → Run workflow 에 이전 태그 |
| 특정 버전으로 | `./deploy.sh sha-1e9845b` |

지금 버전과 바로 앞 버전은 `.deployed-tag`·`.previous-tag` 에 적혀 있고, 그 두 이미지는 지우지 않고 남깁니다.

**DB 는 되돌아가지 않습니다.** 새 버전이 마이그레이션(V 파일)을 적용한 뒤 되돌리면 옛 코드가 새 스키마를 만납니다. 그래서 스키마 변경은 **열·테이블을 더하기만** 하고, 지우는 건 다음 배포로 미룹니다.

### 백업과 되살리기

- **"외부 API 실패 (호스트별)" 칸**은 바깥 API 호출 중 성공이 아닌 것을 호스트·상태 코드별로 셉니다(`http_client_requests_seconds`). 토스 허용 IP 가 바뀌면 `openapi.tossinvest.com 403` 이 여기 바로 뜹니다. 아래에 호스트별 호출 수와 평균 지연 칸이 있습니다. Claude 호출은 SDK 라 여기 안 잡힙니다
- **"응답 시간 대략 p95" · "1초 넘은 요청 비율"** 칸은 `http.server.requests` 의 버킷 네 개(100ms·300ms·1s·3s, `application.yml`)로 그립니다. 버킷이 적어 p95 는 짐작이고 추세를 봅니다
- **Claude 칸**은 호출 수(종류·성공/실패)와 토큰(제값·캐시쓰기·캐시읽기·출력)입니다. SDK 호출을 앱이 직접 재서 남깁니다(`ClaudeMetrics`)
- 관측 컨테이너가 실패해도 앱 배포는 계속됩니다(`deploy.sh` 가 경고만 남김)

### 알림

Prometheus 가 `deploy/monitoring/alerts.yml` 의 규칙을 15초마다 보고, 맞으면 Alertmanager 가 텔레그램으로 보냅니다(`.env` 의 `TELEGRAM_BOT_TOKEN`·`TELEGRAM_CHAT_ID`, 앱의 13F 알림과 같은 봇). 값이 없으면 보내지 않고 Alertmanager 화면에만 쌓입니다.

| 알림 | 언제 | 먼저 할 일 |
|---|---|---|
| `AppDown` (치명) | 앱 지표를 2분째 못 긁음 | `docker compose ps`, `docker compose logs app`. 배포 중이면 되돌림이 됐는지 |
| `TossForbidden` | 토스가 10분 안에 403 | 허용 IP 등록(앱 로그 오류 문구에 지금 IP). 401 은 재시작 직후 정상이라 안 알림 |
| `ExternalApiFailing` | 한 호스트가 15분에 10번 넘게 실패, 5분 지속 | Grafana 외부 API 칸에서 상태 코드 → 아래 장애 대응 표 |
| `High5xxRatio` | 5xx 가 5% 넘게 10분 | `docker compose logs app` 에서 ERROR |
| `HeapNearLimit` | 힙이 512MB 의 90% 를 15분 | 계속 오르면(누수) 재배포로 버티고 원인 찾기 |
| `DiskSpaceLow` | 디스크 여유 10% 밑 | `df -h`, `docker image prune`, `backups/` |
| `ClaudePromptCacheDead` | 분석을 돌렸는데 캐시 읽기 0 | 프롬프트 조립 코드를 바꿨는지. 에러 없이 요금만 오르는 상태 |
| `ClaudeTokensHigh` | 하루 토큰 200만 초과 | 반복 실행 확인. 기준은 짐작이라 몇 주 본 뒤 조정 |
| `CircuitBreakerOpen` | 한 호스트의 서킷 브레이커가 5분 안에 열림 | 그 호스트가 계속 실패해 30초씩 호출을 멈추는 중. 상대 장애인지 키·IP 문제인지 앱 로그 |

- 같은 경보는 4시간마다(치명은 1시간마다) 다시 옵니다. 해결되면 [해결] 이 한 번 옵니다

## 부하 테스트

공개 화면이 부르는 13F 조회 주소(DB 만 읽음)에 k6 로 부하를 줍니다. 스크립트는 `loadtest/` 에 있습니다.

| 파일 | 무엇 |
|---|---|
| `loadtest/public-read.js` | 사람처럼(요청 사이 1초) 동시 사용자 0 → 10 → 30 → 0. 목표: 실패 1% 미만, p95 500ms |
| `loadtest/stress.js` | 쉬지 않고 동시 사용자 0 → 50 → 100 → 0. 몇 건까지 버티는지 |

```bash
# 1) 호출 한도를 올린 별도 인스턴스를 띄운다 (운영 중인 앱에 대고 돌리지 않는다. 한도 120/분에 바로 막힌다)
java -jar target/portfolio-0.0.1-SNAPSHOT.jar --server.port=18080 --management.server.port=18081 --rate-limit.public-per-minute=1000000
# 2) k6 (도커). 컨테이너 안에서 내 PC 는 host.docker.internal
docker run --rm -v "$PWD/loadtest:/scripts" grafana/k6:0.54.0 run /scripts/public-read.js
```

**결과 (2026-10-03~04, 내 PC — 앱과 k6 가 같은 PC)**

| 단계 | 처리량 | 첫 화면 p95 | 기관 상세 p95 | 실패 |
|---|---|---|---|---|
| 처음 (`public-read`, 30명) | 5.2건/초 | **8.8초** | **5.0초** | 0% |
| 고친 뒤 (`public-read`, 30명) | 53건/초 | **0.099초** | **0.039초** | 0% |
| 고친 뒤 한계 (`stress`, 100명) | 약 228건/초 | p95 1.7초 (전체) | | 0% |

**찾은 병목과 고친 것**
1. "같이 산 종목" 이 요청마다 9곳 × 두 분기 보유(수만 줄)를 다시 비교해 한 번에 1.5~2초. 동시 요청이 몰리면 줄을 서서 8초가 됐다 → 13F 조회 결과를 메모리에 두고 **배치가 데이터를 바꾸면 비운다**(`QueryCache`, `ThirteenFDataChangedEvent`). 시간 만료가 없어 묵은 값을 줄 일이 없다
2. 피델리티 보유·변화 응답이 0.9~1.1MB(5천 줄을 통째로) → `limit` 을 두고 화면은 위 100줄만 먼저 받는다(17KB). "모두 보기" 를 누를 때만 전부

**한계에 대해.** 228건/초는 앱과 k6 가 같은 PC 의 CPU 를 나눠 쓴 값입니다. 서버를 만들면 서버에 대고 다시 잽니다. 첫 요청(캐시가 빈 상태)은 여전히 1~4초라, 배치 직후 미리 한 번 계산해 두는 것(예열)이 다음 개선 거리입니다.

| 해외 주식 평가금액이 비정상적으로 작음 | 환율 실패 | 지금은 계산을 포기하고 이유를 띄움 |
| 배당 캘린더에서 "상장사를 찾지 못했습니다" | 회사 이름이 공시·종목 마스터와 다름 | 6자리 종목코드로 넣기. 비슷한 이름으로 넘겨짚지 않게 일부러 막음 |
| 배당 지급일이 "미정" | 회사가 공시에 지급일을 "-" 로 냄 | 정상. 원문(DART 링크)에서 확인 |
| 로그에 "배당 공시를 읽지 못해 건너뜀" | 양식이 다른 공시 | 접수번호로 원문을 열어 `DividendParser` 정규식 확인. 잘못 저장되진 않음(건너뜀) |

### 토스 403 — 허용 IP

가장 자주 겪습니다. 토스가 막히면 **모든 종목의 시세**가 안 옵니다. 시세를 토스에서만 받기 때문에 나무 종목도 가격이 빕니다. 앱 자체는 계속 뜨고 나무 잔고는 보입니다.
에러 메시지가 지금 공인 IP 를 직접 알려주니 그 값을 등록하면 됩니다. 근본 해결은 고정 IP 서버입니다.

### 토스 429 — 호출 한도

계좌 목록을 연달아 부르면 걸립니다. `TOSS_ACCOUNT_SEQ` 를 적어두면 계좌를 매번 조회하지 않습니다.
종목 마스터를 받을 때 시장 일곱 개를 연달아 부르면 **나스닥과 코스닥이 에러 없이 통째로 빠졌습니다.** 그래서 시장 사이에 3초씩 쉽니다.

### 나무

- **403 인데 키는 맞음**: `application/x-www-form-urlencoded;charset=UTF-8` 이면 게이트웨이가 거부합니다. 스프링은 charset 을 끄는 설정이 없어 폼 문자열을 직접 만들어 바이트로 보냅니다
- **성공인데 코드가 00000 이 아님**: 잔고 조회는 `00166` + "조회가 완료되었습니다" 로 옵니다. 코드가 아니라 데이터가 왔는지로 판단합니다

### 클로드

- **400 크레딧 부족**: 키는 정상이고 잔액만 없습니다
- **`fromEnv()` 를 쓰면 안 됩니다**: 이 앱은 `.env` 를 System Property 로 넣습니다. `fromEnv()` 는 OS 환경변수와 로그인 프로파일을 봐서 키를 못 찾거나 **다른 개인 계정으로 과금될 수 있습니다**
- **분석 내용이 이상함**: 자바가 아니라 `src/main/resources/prompts/company-analysis-system.md`(규칙)와 `company-analysis-schema.json`(형식)을 고치고 재시작합니다
- **모델이 "클로드 코드 CLI" 로 나옴**: 2026-09-21 에 크레딧 없이 CLI 로 같은 프롬프트를 돌려 넣은 분석입니다. 공시 재무를 붙이기 전이라 재무는 웹 조사 기준입니다. "다시 분석" 을 누르면 덮어씁니다(유료)

### 공시 재무가 안 붙음

먼저 0원 미리보기(`GET /api/financials/{코드}`)로 봅니다. 404 면 로그에 이유가 찍힙니다.

| 로그 | 원인 | 조치 |
|---|---|---|
| `DART 고유번호가 없습니다` | ETF·리츠, 새로 상장한 종목 | ETF 는 정상. 새 종목이면 `POST /api/financials/mappings/refresh` |
| `SEC CIK 가 없습니다` | ETF (SOXL, SPYI 등) | 정상 |
| `DART 오류 010` / `011` | 키가 틀림 | `DART_API_KEY` 확인 |
| `DART 오류 020` | 하루 2만 건 초과 | 다음 날. 분석 한 번에 8건 안팎이라 보통 안 걸림 |
| `SEC EDGAR 티커 매핑 응답을 받지 못했습니다` | `SEC_USER_AGENT` 없음·형식 틀림 | "앱이름 이메일" 로 넣고 재시작 |

**키가 없으면 로그 없이 조용히 건너뜁니다.** 키가 없어도 분석은 웹 조사로 돌아야 해서 일부러 그렇게 했습니다.

- **PER 이 증권사 앱과 다름**: 기준이 다릅니다(최근 4분기·지배주주·보통주+우선주). 응답의 `shareBasis` 를 보세요. 버그가 아닙니다
- **`history` 가 비어 있음**: 토스가 막혔거나 상장한 지 얼마 안 돼 결산일 주가가 없습니다. 없어도 분석은 돕니다
- **미국 종목의 매출·순이익만 빔**: 회사마다 태그가 다릅니다(은행·보험은 매출 태그가 다름). `EdgarFinancialService` 의 후보 목록에 태그를 추가하세요. 태그는 `https://data.sec.gov/api/xbrl/companyfacts/CIK{10자리}.json` 에서 찾습니다

### 차트가 안 뜸

"차트 라이브러리를 불러오지 못했습니다" 면 CDN 이 막힌 것입니다. 이 앱의 유일한 외부 의존성이라 차트만 영향을 받습니다.
"차트를 그릴 데이터가 부족합니다" 면 상장한 지 얼마 안 됐거나 거래가 없는 종목입니다. 120일선은 121번째 봉부터 그려집니다.

### 뉴스가 엉뚱하게 나옴

종목코드가 아니라 이름으로 검색합니다. 예전에 "현대차" 로 삼성전자 기사가 나왔는데, `uri(String)` 이 URL 을 한 번 더 인코딩해 한글이 `%25EA...` 로 깨진 탓이었습니다. 지금은 `uri(URI.create(url))` 로 고쳐져 있습니다.

### 스크린샷에서 종목을 못 찾음

종목 마스터가 비어 있을 수 있습니다. `GET /api/symbols/status` 로 건수를 보고(약 15,000 이 정상) 적으면 `POST /api/symbols/refresh`.
이름이 비슷한 다른 회사로 가는 건("삼송전자" → 삼영전자) 고칠 수 없는 한계라, 확신이 낮으면 노랗게 표시하고 사람이 확인합니다.

### 해외 주식 금액이 1,380배 작음

환율이 1 로 계산된 경우였습니다($136 → 136원). 지금은 환율을 못 가져오면 계산을 포기하고 이유를 띄웁니다 → [결정기록 005](결정기록.md#005-환율을-못-구하면-예외를-던진다)

### 장애 기록 양식

알림이 울렸거나 사용자가 이상을 봤으면, 끝난 뒤 아래를 채워 [개발일지](개발일지.md)에 덧붙입니다. 같은 증상이 두 번째로 나오면 위 표에 한 줄을 더합니다.
목적은 탓할 사람을 찾는 게 아니라 **다음에 더 빨리 알고, 덜 망가지게** 하는 것입니다(실무의 "비난 없는 회고").

```text
### 장애: (한 줄 요약)  YYYY-MM-DD

- 무엇이: 사용자가 본 증상 (예: 공개 화면 차트가 전부 빔)
- 언제 알았나: 알림 이름과 시각 / 사람이 먼저 봤으면 그 경위
- 얼마나: 시작 ~ 복구 시각, 영향 범위 (공개 화면 / 내 화면 / 배치)
- 원인: 확인된 것만. 추측이면 "추측" 이라고 쓴다
- 조치: 무엇을 해서 복구했나 (명령·PR 번호)
- 재발 방지: 알림이 늦었으면 규칙 고치기, 원인이 코드면 테스트, 절차면 이 문서
```
