## 목표

**증권사 IT 실무와 닮은 경험을 이 프로젝트로 쌓는다.** 기능을 늘리는 것보다 배포하고, 운영하고, 장애를 겪고 고치는 경험이 목표입니다.

증권사 IT 가 중요하게 보는 건 화려한 기능보다 세 가지입니다. 단계마다 이 셋 중 무엇을 연습하는지 적었습니다.

| | 뜻 | 이 프로젝트에서 |
|---|---|---|
| **틀리지 않는다** | 숫자가 정확하고 검증된다 | 앱이 계산한 숫자, 공시 원본, 대사(잔고 맞춰보기) |
| **멈추지 않는다** | 바깥이 죽어도 버틴다 | 외부 연동 실패 격리, 재시도, 헬스체크, 자동 롤백 |
| **추적된다** | 무슨 일이 있었는지 남는다 | 로그, 지표, 알림, 장애 기록, 결정기록 |

### 선을 그어둔 것

- **판정·적정가는 나만 봅니다.** 불특정 다수에게 종목별 매매 의견을 주면 유사투자자문업 신고 대상일 수 있습니다. 정확한 범위는 공개 전에 확인합니다
- **남의 증권사 키를 보관하지 않습니다.** 사용자마다 자기 토스 설정에 서버 IP 를 등록해야 하고, 토큰 하나로 24시간 계좌를 볼 수 있습니다 → [결정기록 004](결정기록.md#004-증권사-로그인을-포기하고-스크린샷으로-우회한다)
- **주문 기능은 만들지 않습니다** → [결정기록 001](결정기록.md#001-주문-api를-만들지-않는다)

그래서 방향은 둘입니다. **개인 앱은 나 혼자 쓰되 실제로 배포해서 운영**하고(1~4단계), 사람을 모으는 건 **공개 자료(13F·DART)로 만든 기능을 따로 엽니다**(5단계).

## 비용 줄이기 (측정 후 결정)

분석 한 번의 값은 웹검색 때문에 턴이 몇 번 끊기느냐에 따라 4배까지 벌어집니다(추정: 보통 807원, 최대 1,558원). 프롬프트 캐싱·뉴스 하쿠 전환·스크린샷 축소는 이미 했습니다. 남은 건 **실측 후에** 하나씩 합니다.

- [x] **이미 가진 자료로 검색 줄이기** (2026-10-06): 뉴스 제목(RSS)·기관 보유(13F)를 프롬프트에 넣고, 재무·과거 배수·뉴스·기관 동향은 검색 금지. 예전에는 [과거 배수] 를 넣고도 "과거 PER 범위 검색" 을 시키고 있었다. 웹검색 상한 8 → 5
- [x] **재무 표는 앱이 붙이고 모델은 해석만** (2026-10-06, [결정기록 017](결정기록.md#017-재무-표는-앱이-붙이고-모델은-해석만-쓴다)). 화면은 그대로
- [x] **두괄식·중복 금지** (2026-10-06): 길이 상한은 두지 않고, 섹션마다 첫 문장이 결론, 앞에서 한 말은 되풀이하지 않게 지시문만 고침
- [x] **판단만 새로** (2026-10-06, [결정기록 018](결정기록.md#018-조사와-판단을-나눠-판단만-새로-쓸-수-있게-한다)). 조사가 7일 안이면 판정·요약·내 위치·위험만 검색 없이
- [ ] 크레딧 충전 뒤 첫 분석에서 위 넷의 효과를 로그로 확인(`claude_tokens_total`, 웹검색 횟수, 출력 토큰)
