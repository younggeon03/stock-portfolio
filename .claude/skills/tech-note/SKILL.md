# 기술노트 갱신

`docs/기술노트.md` 는 이 저장소를 교재로 백엔드·DB·프론트·배포·인프라를 공부하는 노트다.
코드가 바뀌면 문서가 늦게 따라가 틀린 숫자가 남는다. 이 스킬은 **코드에서 사실을 다시 뽑고, 달라진 절만 고친다.**
그리고 같은 원본으로 **HTML 판**(목차 고정·용어 찾기·용어 풍선)을 다시 만들어 Artifact 로 올린다.

답과 진행 보고는 한국어로 한다.

## 0. 누구를 위해 쓰나

**자바 문법·예외·컬렉션은 알지만 실무 용어는 모르는 주니어.** 프록시, 멱등, 서킷 브레이커, readiness, 대사 같은 말을 처음 본다고 가정한다(사용자가 정한 수준, 2026-10-09).

- 자바 문법은 설명하지 않는다. 스프링·DB·네트워크·운영 용어는 **처음 나올 때 풀어 쓴다**
- 새 기술을 설명할 때는 **기초부터 → 이 프로젝트에서는 → 실무에서는** 순서. "기초부터" 에는 그 기술이 없으면 무엇이 불편한지를 먼저 보이고(짧은 코드나 흐름 그림), 그다음 해결을 보인다(2.1 DI, 2.7 프록시, 5.2 CSRF 가 본보기)
- 비유는 한 줄이면 충분하다. 비유가 설명을 대신하면 안 된다

## 1. 지금 사실 뽑기

저장소 루트에서:

```bash
node .claude/skills/tech-note/scripts/facts.js
```

마이그레이션 수·마지막 버전, 테이블·엔티티 목록, 테스트 수(어림), CI 잡 이름, compose 서비스, 프롬프트 파일, 화면 HTML 이 나온다.

## 2. 무엇이 바뀌었나 찾기

1. 노트가 마지막으로 바뀐 커밋 이후의 변경을 본다
   ```bash
   git log --oneline -1 -- docs/기술노트.md
   git diff --stat <그 커밋>..HEAD -- src deploy .github docker-compose.yml Dockerfile loadtest
   ```
2. 바뀐 파일을 아래 표로 노트의 장에 연결한다. 해당 장만 고친다. 바뀌지 않은 장은 건드리지 않는다

| 바뀐 곳 | 고칠 장 |
|---|---|
| `db/migration/V*.sql`, `domain/*.java` | 1.5 데이터, **3장 전체**(ERD 3.1, 요약표 3.2, 마이그레이션 표 3.8) |
| `external/**`, RestClient·재시도 설정 | 1.6 바깥 시스템, 4장 |
| `SecurityConfig`, 요청 제한, CSP | 1.8 보안 경계, 5장 |
| `static/**` | 1.4 화면 지도, 6장 |
| `src/test/**` | 7장 (테스트 수) |
| `Dockerfile`, `docker-compose.yml`, `pom.xml` | 8장 |
| `.github/workflows/**` | 1.10, 9장 |
| `deploy/**` | 1.2 실행 단위, 10장, 11장 |
| 비동기·배치·캐시·`@Scheduled` | 1.2(배치 시각), 1.7, 2.4 |
| 새 필터·인터셉터·`@Transactional` 저장 빈 | 2.7 프록시 표 |

3. 숫자는 노트 안에서 같이 고친다: `grep -n "테이블 [0-9]*개\|V1~V[0-9]*\|[0-9]*개" docs/기술노트.md`
4. 이미 한 일을 "해 보세요" 로 남긴 **직접 해보기** 가 없는지 본다(예전 4장의 "Resilience4j 붙여 보기" 가 그랬다)

## 3. 쓰는 규칙

### 구조

- **각 장 첫머리**에 인용 상자 둘. HTML 판이 이 모양을 읽어 상자·칩으로 그리므로 글자 그대로 지킨다
  ```markdown
  > **이 장에서 배울 것** — 한두 문장.
  >
  > **먼저 알아둘 말** — [용어](#0x-갈래-앵커) · [용어](#0x-갈래-앵커)
  ```
  "먼저 알아둘 말" 의 링크 글자는 0장 표의 용어(또는 그 일부, `·` 로 나눈 조각)와 같게 쓴다. HTML 판은 링크 글자로 용어를 찾아 풍선에 뜻을 띄운다
- **각 절**은 무엇 → (기초부터) → 이 프로젝트에서는 → 실무에서는 → 공부할 것 순서
- 과제는 `> **직접 해보기** — ...` 한 줄 인용으로 쓴다(HTML 판에서 노란 과제 상자가 된다)

### 0장 용어집

- 본문에 **새 실무 용어**가 들어가면 0장의 맞는 갈래(0.1 웹·네트워크 … 0.9 테스트) 표에 한 줄 더한다. 칸은 셋: `**용어**` | 뜻 (비유) | 이 저장소에서(파일·클래스·절)
- 용어 칸에 여러 이름을 `·` 로 묶을 수 있다(`**재시도 · 지수 백오프 · 지터**`). HTML 판의 찾기·풍선이 조각마다 찾는다
- 갈래 제목(`### 0.1 웹과 네트워크`)을 바꾸면 앵커가 바뀌어 장 첫머리 링크가 전부 깨진다. 바꿨으면 linkcheck 로 확인
- 이 저장소에 없는 것을 "이 저장소에서" 칸에 쓰지 않는다. 없으면 "쓰지 않음" 이나 "아직 없음" 이라고 쓴다

### 그림과 글

- **다이어그램은 Mermaid 를 쓰지 않는다.** 편집기에서 영어 코드로 보인다(사용자가 지적함). ` ```text ` 블록 안에 상자 그림(`┌─┐│└┘├┤┬┴ ▼ ┊`)으로 그린다
- 한글은 고정폭 글꼴에서 두 칸이라 **오른쪽 세로선이 어긋나기 쉽다.** 오른쪽 테두리가 필요 없으면 빼고 그린다(2.7 처럼 왼쪽 선과 화살표만). HTML 판은 나눔고딕코딩(한글 정확히 두 칸)으로 그리므로 거기서 맞으면 IntelliJ(D2Coding)에서도 맞다
- **ERD 표기**는 3.1 의 범례를 따른다: `PK`·`UK`·`IX`, 실선 `│`(부모·자식), 점선 `┊`(같은 값으로 찾아볼 뿐). 이 DB 에는 FK 제약이 없다. 새 FK 가 생기면 3.4 를 고친다
- 예시 코드는 짧게, 실제 클래스 이름을 쓰되 줄였으면 "모양만 줄였다" 고 밝힌다
- 도메인(주식·공시) 설명은 최소로. 기술과 실무 연결이 중심이다
- 코드에 없는 걸 지어내지 않는다. 클래스·파일 이름은 실제로 있는지 `grep` 으로 확인하고 쓴다
- "왜 그렇게 정했나" 가 두 문단 넘으면 `docs/결정기록.md` 에 있는지 보고 링크를 건다. 같은 내용을 두 곳에 쓰지 않는다
- **공개 저장소다.** 실제 잔고·수량·평단가·계좌·IP 를 쓰지 않는다. 예시는 데모 값

## 6. HTML 판 다시 만들기

원본은 마크다운 하나다. HTML 은 결과물이라 **저장소에 넣지 않는다**(`target/` 에 만들고 git 이 무시한다).

```bash
node .claude/skills/tech-note/scripts/build-html.js    # → target/tech-note/기술노트.html
```

- 템플릿은 `html/template.html`. 디자인은 저장소의 "브리핑" 토큰(`static/public/tokens.css`)을 옮긴 것이다: 종이색 바탕 하나, 큰 제목만 명조, 강조는 검정, **빨강·파랑은 쓰지 않는다**(등락 전용, 결정기록 008). 글꼴은 Artifact 가 Google Fonts 만 허용해서 Noto Serif KR(제목)·IBM Plex Sans KR(본문)·Nanum Gothic Coding(코드·상자 그림)
- 템플릿을 고쳤으면 게시 전에 크롬 헤드리스로 한 번만 본다. 헤드리스는 스크롤한 화면을 못 찍고 창 폭 500px 아래는 잘려 보인다(페이지 문제 아님). 깊은 절을 보려면 임시 사본에서 `marked.parse(NOTE_MD.slice(NOTE_MD.indexOf("### 2.7")), ...)` 처럼 잘라서 찍고, 사본과 스크린샷은 지운다
- **게시**: Artifact 도구로 `target/tech-note/기술노트.html` 을 올린다. 이미 올린 게 있으면 새 링크를 만들지 말고 `action: "list"` 로 "기술노트" 를 찾아 그 `url` 로 갱신한다(읽기 → 게시). 링크는 사용자에게만 알리고 **저장소 문서에 적지 않는다**
- 템플릿이 하는 일: 본문 "목차" 절 숨김(왼쪽 목차와 겹쳐서), 제목에 GitHub 와 같은 앵커, 다른 문서 링크(`운영.md#...`)는 GitHub 원본으로, 0장 표에서 용어를 읽어 찾기 상자와 풍선에 씀

## 7. 마무리

저장소 절차를 따른다: 브랜치 → 커밋 → PR → CI 통과 → 스쿼시 병합. `main` 에 직접 푸시하지 않는다.
병합한 뒤 HTML 판을 다시 만들어 같은 Artifact 에 게시한다(바닥글에 커밋 번호가 찍혀 원본과 맞는지 보인다).
사용자에게는 **고친 장과 그 이유**, 새로 넣은 용어, 링크 검사 결과, HTML 판 링크를 짧게 보고한다.
