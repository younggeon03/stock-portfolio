# 기술노트 갱신

`docs/기술노트.md` 는 이 저장소를 교재로 백엔드·DB·프론트·배포·인프라를 공부하는 노트다.
코드가 바뀌면 문서가 늦게 따라가 틀린 숫자가 남는다. 이 스킬은 **코드에서 사실을 다시 뽑고, 달라진 절만 고친다.**
그리고 같은 원본으로 **HTML 판**(목차 고정·용어 찾기·용어 풍선)을 다시 만들어 Artifact 로 올린다.

답과 진행 보고는 한국어로 한다.

## 0. 누구를 위해 쓰나

**자바 문법·예외·컬렉션은 알지만 실무 용어는 모르는 주니어.** 프록시, 멱등, 서킷 브레이커, readiness, 대사 같은 말을 처음 본다고 가정한다(사용자가 정한 수준, 2026-10-09).

- 자바 문법은 설명하지 않는다. 스프링·DB·네트워크·운영 용어는 **처음 나올 때 풀어 쓴다**
- 새 기술을 설명할 때는 **기초부터 → 이 프로젝트에서는 → 실무에서는** 순서. "기초부터" 에는 그 기술이 없으면 무엇이 불편한지를 먼저 보이고(짧은 코드나 흐름 그림), 그다음 해결을 보인다(2.1 DI, 2.7 프록시, 5.2 CSRF 가 본보기)
- 비유는 한 줄이면 충분하다. 비유가 설명을 대신하면 안 된다
- **문체는 "~이다, ~한다"** (사용자 지정, 2026-10-09). "~입니다"를 쓰지 않는다. 표 칸도 끝맺은 문장으로 쓰고 "~함", "~않게", "→ 고침" 같은 조각으로 끝내지 않는다
- 글머리표를 늘어놓지 말고 **이어지는 문단**으로 쓴다(왜 → 그래서 → 어떻게). 조사는 붙여 쓴다(`Caddy가`, `API를`)
- 2026-10-09 에 전체(0~15장)를 이 문체로 다시 썼다. 새 절도 같은 문체로 쓰고, 고친 뒤에는 "니다." 와 조사 앞 띄어쓰기가 남지 않았는지 훑어본다

## 3. 쓰는 규칙

### 구조

- **각 장 첫머리는 지도 → 안내 → 요약 상자 순서다** (사용자 요청, 2026-10-09: "새로운 단락 들어갈 때마다 첫 부분에 다이어그램 넣고, 이제 어디 부분 할 거고 어떻게 연결되어 있는지 설명 먼저"). 장 제목 바로 아래에:
  ```markdown
  ## 4. 외부 API 연동

  <!-- diagram: map@external,extapi | 4장은 service 옆의 external 층과, 그 너머의 바깥 API를 본다. -->

  **지도에서 보면.** 앞 장에서 무엇을 봤고, 이 장은 지도의 어디이며, 그 부분이 앞뒤의 무엇과 어떻게 이어지는지 2~4문장.
  ```
  `map@` 뒤의 이름은 `html/diagrams.js` 의 `D.map` 노드 `part` 값이다(browser, caddy, web, service, domain, external, extapi, mysql, monitoring, code, ci, image, deploy). 1장은 `map`(전부 진하게). 0장(용어집)·13장(공부 순서)·14장(면접)은 시스템의 한 부분이 아니라 지도를 두지 않는다. 새 장을 만들면 지도와 안내 문단도 같이 쓴다. 시스템에 새 부품이 생기면(예: Redis) `D.map` 에 노드와 `part` 를 더한다
- 그다음 인용 상자 둘. HTML 판이 이 모양을 읽어 상자·칩으로 그리므로 글자 그대로 지킨다
  ```markdown
  > **이 장에서 배울 것** — 한두 문장.
  >
  > **먼저 알아둘 말** — [용어](#0x-갈래-앵커) · [용어](#0x-갈래-앵커)
  ```
  "먼저 알아둘 말" 의 링크 글자는 0장 표의 용어(또는 그 일부, `·` 로 나눈 조각)와 같게 쓴다. HTML 판은 링크 글자로 용어를 찾아 풍선에 뜻을 띄운다
- **각 절**은 무엇 → (기초부터) → 이 프로젝트에서는 → 실무에서는 → 공부할 것 순서
- 과제는 `> **직접 해보기** — ...` 한 줄 인용으로 쓴다(HTML 판에서 노란 과제 상자가 된다)

### 0장 용어집

- 본문에 **새 실무 용어**가 들어가면 0장의 맞는 갈래(0.1 웹·네트워크 … 0.9 테스트) 표에 한 줄 더한다. 칸은 셋: `**용어**` | 뜻 (비유) | 이 저장소에서(파일·클래스·절)
- 용어 칸에 여러 이름을 `·` 로 묶을 수 있다(`**재시도 · 지수 백오프 · 지터**`). HTML 판의 찾기·풍선이 조각마다 찾는다
- 갈래 제목(`### 0.1 웹과 네트워크`)을 바꾸면 앵커가 바뀌어 장 첫머리 링크가 전부 깨진다. 바꿨으면 linkcheck 로 확인
- 이 저장소에 없는 것을 "이 저장소에서" 칸에 쓰지 않는다. 없으면 "쓰지 않음" 이나 "아직 없음" 이라고 쓴다

### 그림 — 글자 그림과 실제 그림을 한 쌍으로

HTML 판에서는 **글로 그린 그림을 보여 주지 않는다**(사용자 요청, 2026-10-09: "다이어그램이나 이런 거 글로 적지 말고, 이미지나 실제 다이어그램을 활용"). 그림 하나는 두 곳에 있다.

| 어디 | 무엇 | 왜 |
|---|---|---|
| `docs/기술노트.md` | ` ```text ` 상자 그림 + 바로 위의 `<!-- diagram: 이름 \| 설명 -->` | IntelliJ·GitHub 에서도 그림이 보여야 한다. 주석 줄은 GitHub 에서 안 보인다 |
| `html/diagrams.js` | 같은 내용의 그림 명세(노드·선·라벨 좌표) | 빌드 때 SVG 로 그려 글자 그림 자리에 넣는다. 글자 그림은 "글로 그린 그림 보기" 로 접힌다 |

- **글자 그림을 더하거나 고치면 `diagrams.js` 명세도 같이 고친다.** 둘이 다른 말을 하면 안 된다. 표시 없는 ` ```text ` 가 있거나, 표시가 가리키는 그림이 없으면 `build-html.js` 가 멈춘다
- 표시의 설명(`|` 뒤)은 **그림이 말하는 한 문장**이다. HTML 판의 그림 밑 설명과 화면 낭독기용 `aria-label` 이 된다
- 명세 쓰는 법은 `diagrams.js` 맨 위 주석에 있다. `N(x, y, w, h, 제목, 보조, 종류)` 노드, `T(...)` 표(ERD), `E(path, 라벨, lx, ly)` 선, `zones` 경계. 종류: `main`(이 그림의 주인공, 굵은 테두리) · `ext`(바깥) · `db`
- **그리는 규칙**:
  - 메커니즘을 그린다. 상자 이름만 늘어놓지 말고 무엇이 어디로 흐르는지, 어느 경계를 넘는지 보이게 한다
  - **선에는 라벨**(`HTTPS 443`, `없으면`, `15초마다 긁음`)을 단다. 라벨 없는 선은 "어딘가 관련 있음" 일 뿐이다
  - 폭은 720 이 본문에 맞는다. 상자 사이는 라벨 길이 + 20 이상 띄운다(한글 12px 라벨은 한 글자 약 12px). 라벨이 상자·선·경계선에 닿으면 안 된다
  - 색은 템플릿의 토큰(`.d-*` 클래스)만. 빨강·파랑 금지. 강조는 굵은 검정 테두리(`main`)
  - 같은 갈래로 나가는 선은 한 지점에서 갈라지게(포크) 그린다. 다른 상자의 테두리를 타고 지나가게 그리지 않는다
- **고친 그림은 크롬으로 반드시 본다.** 여러 그림을 한 번에 보려면 빌드한 HTML 의 `marked.parse(NOTE_MD,` 를 `marked.parse("### 이름\n\n<!-- diagram: 이름 | 이름 -->\n", ` 처럼 바꾼 임시 사본을 찍는다(6장). 2026-10-09 첫 그리기에서 라벨이 상자에 붙은 것 6군데, 표 마지막 줄이 테두리에 걸린 것, 갈래 선 하나가 끊긴 것을 이렇게 찾았다
- 손으로 그린 SVG 가 더 나으면 `html/diagrams/이름.svg` 로 둔다(1.1 `overview.svg`). 같은 이름이면 이 파일이 이긴다. `<style>`·`<script>` 는 넣지 않고 템플릿의 `.d-*` 클래스를 쓴다

### 오른쪽 칸 — 단락마다 실제 코드

HTML 판은 세 단이다(사용자가 후보 셋 중 C를 고름, 2026-10-09): 왼쪽 목차 · 가운데 본문(780px) · 오른쪽 칸(420px). 오른쪽 칸은 **단락(### 4.1 …)마다 따로** 있고, 그 단락을 읽는 동안 따라 내려온다. 사용자 요청: "각 문단 우측에 … 이해를 쉽게 할 수 있도록 실사용된 코드나 구조, 다이어그램, 그림 등이 들어갔으면".

- 내용은 `html/sides.js` 에 단락 번호를 키로 적는다. 단락이 없는 장(7·12장)은 장 번호가 키다
- **코드는 손으로 옮겨 적지 않는다.** `{ file, from, lines | to, exact, lang, note }` 로 "어느 파일의 어디서 어디까지"만 적으면 빌드가 저장소에서 잘라 온다. 코드가 바뀌어 `from` 이 사라지면 빌드가 멈춘다. 그때는 새 위치를 찾아 고친다(지우지 말고)
- 잘라 온 결과는 `node .claude/skills/tech-note/scripts/build-html.js --sides` 로 단락마다 첫 줄·끝 줄을 보고 확인한다. 메서드 중간에서 끊기거나 다음 메서드 첫 줄이 딸려 오면 `lines` 를 조정하거나 `to` 를 쓴다
- 같은 글자가 앞쪽에 또 있으면 `exact: true`(줄 전체가 같을 때만)를 쓴다. 1.8 이 그 예다
- `note` 는 "이 코드에서 무엇을 보라는지" 한 문장. 본문을 되풀이하지 말고 코드의 어느 줄이 본문의 어느 말에 해당하는지 짚는다
- 고를 때: 본문이 말하는 메커니즘이 **실제로 일어나는 줄**을 고른다(설정값, 분기, 애노테이션, SQL 제약). 클래스 전체나 import 는 넣지 않는다. 30줄을 넘기면 줄인다
- 본문에 이미 있는 그림은 오른쪽 칸에 다시 넣지 않는다. 코드로 보여 줄 게 없는 단락은 `diagrams.js` 그림이나 `{ code, lang, title }` 예시(명령어 순서 등)를 쓴다
- **공개 저장소다.** `.env` 나 비밀값이 든 파일은 가리키지 않는다. 잘라 온 코드에 실제 IP·키가 섞이지 않았는지 `--sides` 출력으로 본다
- 새 단락을 만들면 `sides.js` 에도 자리를 만든다. 비워 두면 오른쪽 칸이 없는 단락이 되어 레이아웃은 깨지지 않지만 사용자가 원한 모양이 아니다

### 글자 그림과 글

- **글자 그림에 Mermaid 를 쓰지 않는다.** 편집기에서 영어 코드로 보인다(사용자가 지적함). ` ```text ` 블록 안에 상자 그림(`┌─┐│└┘├┤┬┴ ▼ ┊`)으로 그린다
- 한글은 고정폭 글꼴에서 두 칸이라 **오른쪽 세로선이 어긋나기 쉽다.** 오른쪽 테두리가 필요 없으면 빼고 그린다(2.7 처럼 왼쪽 선과 화살표만)
- **ERD 표기**는 3.1 의 표를 따른다: `PK`·`UK`·`IX`, 실선(부모·자식), 점선(같은 값으로 찾아볼 뿐). 이 DB 에는 FK 제약이 없다. 새 FK 가 생기면 3.4 를 고친다
- 예시 코드는 짧게, 실제 클래스 이름을 쓰되 줄였으면 "모양만 줄였다" 고 밝힌다
- 도메인(주식·공시) 설명은 최소로. 기술과 실무 연결이 중심이다
- 코드에 없는 걸 지어내지 않는다. 클래스·파일 이름은 실제로 있는지 `grep` 으로 확인하고 쓴다
- "왜 그렇게 정했나" 가 두 문단 넘으면 `docs/결정기록.md` 에 있는지 보고 링크를 건다. 같은 내용을 두 곳에 쓰지 않는다
- **공개 저장소다.** 실제 잔고·수량·평단가·계좌·IP 를 쓰지 않는다. 예시는 데모 값

## 6. HTML 판 다시 만들기

원본은 마크다운 하나다. HTML 은 결과물이라 **저장소에 넣지 않는다**(`target/` 에 만들고 git 이 무시한다).

```bash
node .claude/skills/tech-note/scripts/build-html.js    # → target/tech-note/기술노트.html
```

- 템플릿은 `html/template.html`. 디자인은 저장소의 "브리핑" 토큰(`static/public/tokens.css`)을 옮긴 것이다: 종이색 바탕 하나, 큰 제목만 명조, 강조는 검정, **빨강·파랑은 쓰지 않는다**(등락 전용, 결정기록 008). 글꼴은 Artifact 가 Google Fonts 만 허용해서 Noto Serif KR(제목)·IBM Plex Sans KR(본문)·Nanum Gothic Coding(코드·상자 그림)
- **레이아웃(세 단)**: 전체 폭 최대 1,680px, 왼쪽 목차 230 · 본문 780(`--measure`) · 오른쪽 칸 420(`--side`). 1,280px 아래에서는 오른쪽 칸이 단락 아래로 내려가고, 960px 아래에서는 목차가 위로 접힌다. 폭 숫자는 template.html 의 `:root` 에만 있다. 2026-10-09 에 후보 셋(A 넓은 한 단, B 그림만 전폭, C 세 단)을 4장으로 만들어 보여 주고 C로 정했다. 레이아웃을 크게 바꿀 때는 같은 방식으로 후보를 만들어 먼저 보여 준다
- **문법 강조**: highlight.js(cdnjs 11.9.0 + dockerfile). 색 없이 굵기와 회색 단계로만 칠한다(`.hljs-*` 규칙). 새 언어가 필요하면 cdnjs 의 `languages/이름.min.js` 를 더한다
- 템플릿을 고쳤으면 게시 전에 크롬 헤드리스로 한 번만 본다. 헤드리스는 스크롤한 화면을 못 찍고 창 폭 500px 아래는 잘려 보인다(페이지 문제 아님). 깊은 절을 보려면 임시 사본에서 `marked.parse(NOTE_MD.slice(NOTE_MD.indexOf("### 2.7")), ...)` 처럼 잘라서 찍고, 사본과 스크린샷은 지운다
- **게시**: Artifact 도구로 `target/tech-note/기술노트.html` 을 올린다. 이미 올린 게 있으면 새 링크를 만들지 말고 `action: "list"` 로 "기술노트" 를 찾아 그 `url` 로 갱신한다(읽기 → 게시). 링크는 사용자에게만 알리고 **저장소 문서에 적지 않는다**
- 템플릿이 하는 일: 본문 "목차" 절 숨김(왼쪽 목차와 겹쳐서), 제목에 GitHub 와 같은 앵커, 다른 문서 링크(`운영.md#...`)는 GitHub 원본으로, 0장 표에서 용어를 읽어 찾기 상자와 풍선에 씀, `<!-- diagram: -->` 표시를 그림으로 바꾸고 `map@부분` 이면 그 부분만 진하게(나머지 흐리게), 같은 그림을 두 번 써도 화살표 id 가 겹치지 않게 그림마다 id 를 새로 붙임
- 빌드가 멈추는 경우: 표시 없는 ` ```text `, 없는 그림 이름. 메시지가 행 번호와 고칠 곳을 알려 준다

## 7. 마무리

저장소 절차를 따른다: 브랜치 → 커밋 → PR → CI 통과 → 스쿼시 병합. `main` 에 직접 푸시하지 않는다.
병합한 뒤 HTML 판을 다시 만들어 같은 Artifact 에 게시한다(바닥글에 커밋 번호가 찍혀 원본과 맞는지 보인다).
사용자에게는 **고친 장과 그 이유**, 새로 넣은 용어, 링크 검사 결과, HTML 판 링크를 짧게 보고한다.

## 8. 진행 중 — 코드 에디터 모양 (2026-10-09, 사용자 확인 대기)

사용자 요청: 오른쪽 칸 코드를 "인터프리터처럼" 검은 배경·문법 색·괄호 색으로, 스크롤은 페이지 하나, 오른쪽 칸은 화면 끝까지, 코드 상자는 단락 높이만큼.

- 샘플(4장만)로 만들어 보여 준 상태다. 덧씌우는 파일은 `html/pending/editor.css`·`editor.js`, 샘플 만들기는 `node .claude/skills/tech-note/html/pending/make-sample.js` (빌드한 HTML 에 덧씌워 4장만 남김. 스크립트 안의 `variants/` 경로는 `html/pending/` 으로 고쳐 쓴다)
- 정한 것: IntelliJ Darcula 계열 색(키워드 #cf8e6d, 문자열 #6aab73, 숫자 #2aacb8, 주석 #7a7e85 기울임, 애노테이션 #b3ae60), 괄호는 깊이마다 #f2c94c·#d278d6·#4fb4f0(문자열·주석 안은 칠하지 않음), 줄마다 [실제 파일 줄 번호 | 코드], 긴 줄은 접기(가로 스크롤 없음), `.shell` 최대 폭 해제, `.sec` 오른쪽 칸 `minmax(420px, 1fr)`, `align-items: stretch` 로 단락 높이만큼. **코드 블록만** 빨강·파랑 금지 규칙의 예외다
- 빌드는 이미 `start`(실제 시작 줄 번호)를 SIDES 에 넘긴다
- Monaco·CodeMirror 는 Artifact 가 바깥 스타일시트를 막아 쓰지 않는다. 같은 겉모습을 직접 만든다
- **남은 결정**(사용자에게 물을 것): 4.4 처럼 코드가 본문보다 길어 본문 아래가 비는 단락을 ① 그대로 둘지 ② 핵심 줄 위주로 줄일지
- 확인을 받으면: `pending/editor.css` 를 template.html `<style>` 에 합치고(옛 `.ref pre`·회색 `.hljs-*` 규칙은 지움), `editor.js` 의 `editor()`·`splitLines()`·`rainbow()` 를 `fillSide` 와 본문 코드 처리에 넣는다. 그다음 `pending/` 을 지우고 이 절을 6장 규칙으로 옮긴다. 사용자 요청대로 **일부 적용 → 확인 → 전체** 순서를 지킨다
